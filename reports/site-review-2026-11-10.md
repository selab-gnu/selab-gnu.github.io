# 홈페이지 상세 검수 · 2026-11-10

## 이번에 개선한 부분

- 갤러리: 행사별 대표 사진 카드, 사진 수, 날짜, 앨범 열기와 사진 확대·이전/다음.
- 앨범 검색과 연도 선택. 데이터 없음, 검색 결과 없음, 로드 실패를 다른 안내로 구분.
- 관리자: 여러 사진 선택(최대 12장), 대표 사진 선택, 사진 삭제, 신규 저장 완료 후 입력 초기화.
- 기존 단일 사진 기록 보존. 같은 제목·날짜로 묶고 기존 Firebase 규칙을 그대로 사용.
- 수정·삭제 시 앨범의 기존 문서 revision을 모두 확인하는 원자적 저장. 실패 때 입력 보존.
- 확대창의 Esc/좌우 방향키와 닫은 뒤 초점 복원, 배경 스크롤 제어.
- 공통 헤더의 영문 검색 안내를 짧게 조정.
- 논문 원문 유지 안내를 논문·검색 화면에만 표시하여 홈·소개·멤버·뉴스·갤러리의 불필요한 문구 제거.

## 검증

로컬 브라우저와 Firebase 모의 데이터로 다중 사진 등록, 대표 카드, 사진 모음, 확대·넘김, 실패/충돌 복구, 권한 제한을 확인합니다. 전체 공개 화면의 한·영 전환과 390/768/1440px 너비, 검색 및 카테고리 이동도 확인합니다. 테스트용 사진은 실제 사이트에 등록하지 않습니다.

## 다음 개선 제안

1. 멤버 소개 중복 정리: 카드의 이름·연구 주제·이메일이 원본 상세 본문에도 반복됩니다. 공개 카드에 필요한 정보만 한 번 보여주도록 구조화하면 읽기 쉬워집니다. 편집 원본은 보존하는 방식이 적절합니다.
2. 논문 검색 진입점 정리: 상단 검색과 Publications 내부 검색이 함께 있습니다. 기능은 동작하지만 안내 문구를 ‘전체 논문 검색’과 ‘현재 목록 내 검색’으로 구분하면 덜 헷갈립니다.
3. 영문 콘텐츠 관리: 사이트 UI는 번역되지만 관리자가 새로 쓰는 뉴스·갤러리 제목/설명은 입력한 원문 그대로입니다. 영어 제목·설명 입력란을 나중에 추가하면 좋습니다.
4. 사진 양이 늘면 목록 페이지 분할 또는 더 보기: 현재는 전체 사진 문서를 조회합니다. 앨범 수가 많아질 때 대표 사진 목록만 먼저 가져오도록 개선할 수 있습니다.
5. 네이버 로그인은 앱·서버 연결 전이며 도입 보류 상태입니다. Google 로그인만 실제 사용할 수 있다는 점을 운영자에게 안내하는 것이 좋습니다.
6. 저장소·Firebase·공개 PPT/PDF에는 원본 연락처가 남아 있으므로 JavaScript 이메일 분리 표기를 완전한 접근 차단으로 안내하지 않아야 합니다.

## 운영상 설명

같은 제목과 날짜의 사진은 같은 행사로 묶입니다. 사진의 순서는 저장된 앨범 문서 ID 순서이며 첫 사진이 대표 사진입니다. 새 앨범을 저장할 때 사진 순서를 고정한 ID를 생성합니다. 사진마다 별도 캡션을 입력하는 UI는 이번 범위에 포함하지 않았으며 앨범 설명을 사용합니다.
